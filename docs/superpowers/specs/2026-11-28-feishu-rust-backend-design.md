# 遥显飞书机器人与 Rust 后端设计说明

日期：2026-11-28

## 目标

在内存为 1 GB 的树莓派上，用一个 Rust 进程替代现有 Python 后端。这个进程继续提供网页后台和电视 WebSocket，并同时作为飞书机器人：在用户指定的飞书群里，群成员可以发送图片或文字，选择是否强制弹出后，客厅里的 Android 电视全屏显示。

树莓派已有公网 IPv6，服务直接听在这台机器上。网页后台保留，飞书是多一种控制方式。

## 不做的事

- 不使用飞书 Webhook 回调，改为使用飞书长连接接收事件
- 不保留 Python 后端进程，由 Rust 进程完全替代
- 不把飞书做成独立的 sidecar 进程
- 不开放私聊控制，只处理指定群
- 不同时服务多台电视。新的电视连接会替换旧的
- 不上架应用商店。安装包侧载
- 不使用 Cloudflare Tunnel，也不使用其他内网穿透
- 不使用 Google Play 服务或 Firebase
- 不把真实密码或飞书凭证写进仓库或日志

## 角色

- 管理页：手机浏览器。登录、发布图片或文字、预览、看电视是否在线、开关强制弹出
- 服务：单一 Rust 进程（Tokio + Axum）。保存当前内容，通过 WebSocket 推给电视，并通过飞书长连接接收指定群的消息
- 电视：现有 Kotlin 应用，需改一版以支持没有图片时全屏显示文字。协议尽量保持兼容
- 飞书群：用户指定的一个或多个群。群内成员发送图片或文字，经卡片确认后发布到电视

## 内容

当前内容只有一份，存在磁盘上（`content.json` 加可选的 `image.jpg` 或 `image.png`）：

- 图片和文字至少要有一样。可以只发图、只发文字，或两者都有
- 图片只接受 JPEG 或 PNG 的文件头，最大 10 MB（10 × 1024 × 1024 字节）。不看扩展名
- 文字去掉首尾空白后最长 4000 字。若去掉空白后为空，视为没有文字
- `force_popup` 布尔值。单独修改时不增加修订号
- `revision` 从 0 开始，每成功发布一条新内容加 1（包括只改文字、只改图）
- `updated_at` 为 UTC 时间

还没有任何内容时，`revision` 为 0，没有图片也没有文字。

服务重启后从磁盘读回，包括现有 Python 服务写下的 `content.json` 和图片，格式保持兼容。电视重连时拿到的就是这份内容。

## 管理页

简体中文，手机优先，服务端渲染。路径和行为与现有服务保持一致，并允许只发文字：

- `GET /login`、`POST /login`、`POST /logout`
- `GET /` 预览当前图片和（或）文字、电视在线或离线、强制弹出是开还是关
- `POST /content` 上传可选图片、可选文字、强制弹出勾选。图片和文字至少要有一样
- `POST /force-popup` 只改开关。已有内容时把同一修订号再推一次，电视不因此抢焦点
- `GET /media/current` 给预览用，要登录。没有图片时返回 404
- `GET /api/status` 返回 `tv_online`、`force_popup`、`has_image`、`has_text`、`revision`、`text`，要登录。页面每 3 秒拉一次，用来刷新在线状态
- `GET /health` 返回 `{"ok": true}`，不登录，给部署检查用

密码来自环境变量 `ADMIN_PASSWORD`。空密码和示例值（包括 `change-me`）拒绝启动，退出信息里不带密码本身。

登录成功后发名为 `tvdisplay_session` 的 HttpOnly、SameSite=Lax Cookie。Cookie 的值是密码的 HMAC，不是密码原文。比较密码和比较令牌都用恒定时间比较。

浏览器如果带了 `Origin`，必须和 `Host` 一致，否则 POST 返回 403。

校验失败时管理页直接显示中文原因，例如「请发送图片或文字」「只支持 JPEG 或 PNG」「图片不能超过 10 MB」。不回显用户刚输入的密码。

关闭 `/docs`、`/redoc` 和 OpenAPI，避免在公网 IPv6 上把接口形状摊开。

## 电视连接

`WS /ws/tv`。密码不放在 URL 里，避免进访问日志。连接建立后，客户端先发一条文本帧：

```json
{"type": "auth", "password": "<管理密码>"}
```

密码不对、正文不是 JSON、或超过 `auth_timeout_seconds`（默认 10 秒）没有这条消息，服务用关闭码 1008 断开，并且不把这台连接算作在线。

通过之后：

1. 若已经有一台电视，用关闭码 4000 断开它，只保留最新的连接
2. 立刻下发当前内容，让刚才离线的电视补上
3. 管理页或飞书之后每发布一次，向这一台连接推一条同样形状的消息

消息：

```json
{
  "type": "content",
  "revision": 1,
  "text": "可选文字",
  "force_popup": true,
  "image_mime": "image/jpeg",
  "image_base64": "<标准 base64，没有图片时为 null>",
  "updated_at": "2026-11-26T06:00:00+00:00"
}
```

还没有任何内容时，`revision` 为 0，`text` 为空字符串，`image_mime` 和 `image_base64` 为 null。只发文字时，`revision` 大于 0，`text` 为正文，`image_mime` 和 `image_base64` 为 null。

在线状态就是「当前有没有这一条 WebSocket」。

抢焦点规则不变：

```text
force_popup 为真，且这次的 revision 大于本机已经展示过的 revision
```

为真：发一条全屏意图通知，并尝试把 `MainActivity` 调到前台。为假：只更新内存里的内容；应用已经开着时画面会换，但不会调用把应用拉到前台的代码。已经展示过的修订号写在偏好里，所以同一次内容的重连不会反复弹出。

## 飞书机器人

服务进程内使用飞书开放平台的长连接接收事件。树莓派主动向外连接，不提供飞书事件回调 URL，也不因此要求域名或 HTTPS。

### 配置

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_ALLOWED_CHAT_IDS`：允许控电视的群 ID，逗号分隔，可指定一个或多个。比较时去掉首尾空白，必须完全匹配

这三项都未配置时，网页后台和电视连接照常工作，飞书功能关闭，启动日志写明「飞书未配置」。三项都配置了但连接失败时，网页和电视不受影响，飞书长连接按退避自动重试：第 `attempt` 次（从 0 开始）等待 `min(1000 << attempt, 30000)` 毫秒。只配了其中一部分则拒绝启动，退出信息说明缺了哪一项，不打印密钥本身。

### 收消息

只处理 `FEISHU_ALLOWED_CHAT_IDS` 里的群。其他群、私聊以及非指定群的事件一律忽略，不回复、不记消息正文。

在指定群里，成员直接发送即可，不必 @机器人。接受：

- 一张 JPEG 或 PNG
- 一段文字
- 两者都有（图片加说明文字）

收到后先校验：至少有图或文字；图片经飞书开放接口下载后检查文件头，最大 10 MB。不合格时在群里用中文回复原因，例如「请发送图片或文字」「只支持 JPEG 或 PNG」「图片不能超过 10 MB」「无法下载图片，请重试」。

校验通过后，不立即发布到电视。服务把这条内容存为待确认项，并在群里回复一张交互卡片，提供两个按钮：「强制弹出」和「普通显示」。卡片上展示将要发布的文字摘要（若有）以及是否带图。

群里任何人点击其中一个按钮后：

1. 写入当前内容，`revision` 加 1，按按钮设置 `force_popup`
2. 若电视在线，立即推送
3. 更新卡片或跟一条中文说明：发送成功；若电视不在线，则说明「已保存，但电视当前不在线」

同一张卡片重复点击：提示「这条已经发送过了」，不再发布、不增加修订号。

待确认项保留 10 分钟，超时后点击提示「这条内容已过期，请重新发送」，不发布。为适应 1 GB 内存，同时最多保留 5 条待确认项；再来新的时，丢掉最早的一条未确认项（若有人随后点被丢掉的卡片，按过期处理）。待确认的图片只保留一份，发布或丢弃后立即释放。

不处理表情、视频、文件、系统消息等其它类型。若明显是用户发来的不支持内容（例如视频或非图片文件），回复「请发送图片或文字」。

### 与管理页的关系

飞书发布和管理页发布写入同一份当前内容。从任一端发布都会推给电视，并反映在管理页预览里。

## 日志

服务日志可以写「登录失败」「电视已连接」「已发布」「飞书已连接」「飞书未配置」「飞书连接已断开」。不可以写密码、Cookie、认证帧正文、飞书密钥、用户的说明文字或群消息正文。进程启动时给日志装上替换过滤器，万一密码或密钥被拼进日志，也替换成 `***`。

## Android 电视

包名 `com.tvdisplay.remote`。连接方式、认证、重连退避和抢焦点规则与现有应用一致。本设计需要改一版并重新侧载：

- 只发文字（`revision` 大于 0，`image_base64` 为 null，`text` 非空）时，全屏显示文字，不再提示「还没发布」
- 还没有任何内容（`revision` 为 0，无图无文字）时，仍说明还没发布
- 有图时仍全屏显示图片，文字作为说明叠在上面，与现在一致

界面文案全部是简体中文。连接状态用「已连接 / 正在重试 / 密码不正确」这类短句，不包含密码。

## 部署

部署方式与现有说明一致，实现时更新 `docs/deploy-raspberry-pi.md`：

- Compose 使用 `network_mode: host`
- 默认 `HOST=::`，`PORT=8080`
- 数据卷挂到 `/data`
- 没有域名：HTTP，文档说明明文密码风险
- 有域名且 AAAA 指向树莓派：可选的 `docker-compose.https.yml` 用 Caddy 申请 Let’s Encrypt，服务改听 127.0.0.1
- 镜像改为适合在树莓派 64 位上运行的 Rust 构建，不再基于 `python:3.12-slim`
- `.env` 增加飞书三项可选配置。示例文件只用占位符，不用真实密钥
- 部署说明需写清：如何创建飞书企业自建应用、开通长连接与群消息相关权限、如何取得群 ID，并写入 `.env`

## 测试

Rust 测试覆盖现有后端用例，并加上新行为：

- 密码比较、示例密码被拒绝、图片类型和 10 MB 上限、磁盘往返（含从现有 `content.json` 格式读回）、登录与中文页面、越权与跨站、WebSocket 补发、推送、后来的连接替换先前的、日志里没有密码或密钥
- 只发文字、只发图、图文都有、两者都缺被拒绝
- 飞书：指定群通过、非指定群忽略、不必 @、卡片按钮分别以 `force_popup` 为真或假发布、重复点击不重复发布、待确认 10 分钟过期、超过 5 条时丢掉最早的、未配置飞书时服务仍能启动

电视端补充单元测试：无图有文字时进入展示状态而不是「还没发布」；抢焦点规则仍只取决于 `force_popup` 与修订号。调试 APK 用 `assembleDebug` 打出。

## 迁移

- 用 Rust 服务替换 `server/` 下的 Python 实现。电视应用做上述改动后重新侧载
- 磁盘上已有的 `content.json` 与图片文件继续有效
- 已部署的 Compose 与数据卷路径保持可用，需更换镜像并按需补上飞书环境变量
